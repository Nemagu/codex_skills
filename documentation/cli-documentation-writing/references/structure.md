# Структура документации CLI

## Иерархия файлов

По умолчанию использовать одно presentation-поддерево:

```text
presentation/cli/
├── README.md
├── output.md
└── commands/
    └── <group>/
        ├── README.md
        └── <action>.md
```

`output.md` создавать при наличии общих форматов, полей ошибки, потоков или
статусов. Если общий контракт отсутствует и CLI состоит из одной простой
команды, эти сведения можно оставить в документе команды.

Каждую конечную команду размещать в отдельном файле. Общие внешние модели
выносить отдельно только при реальном переиспользовании или когда их объём
мешает читать команду. Не создавать пустые каталоги будущих групп и команд.

## Корневой документ

`presentation/cli/README.md` фиксирует:

- потребителей, доверие и границу CLI;
- имя исполняемой команды и общий вид иерархии;
- таблицу групп подкоманд;
- общие опции и значения по умолчанию;
- справку корневого уровня и поведение вызова без подкоманды;
- ссылки на общий вывод, корреляцию и logging-профиль;
- готовность и открытые вопросы.

Описание группы в таблице остаётся кратким и не перечисляет поля конкретных
команд.

## Документ группы

`commands/<group>/README.md` содержит назначение группы, форму вызова, таблицу
действий, справку этого уровня и поведение вызова без действия. Назначение
действия формулировать как краткий результат, например «Обновить сотрудника», а
состав обновляемых сведений оставлять документу команды.

Если иерархия глубже, каждый промежуточный уровень документировать по тем же
правилам: список дочерних команд, собственная справка и неполный вызов.

## Документ конечной команды

Документ действия содержит полный внешний контракт по
[command-contract.md](command-contract.md) и примеры ответов по
[response-examples.md](response-examples.md). Общие опции и модели не копировать;
ссылаться на документ-владелец и описывать только отклонения.

## Навигация

Фрагмент `SUMMARY.md` повторяет фактическую иерархию:

```markdown
- [CLI](./presentation/cli/README.md)
  - [Общий контракт вывода](./presentation/cli/output.md)
  - [Название группы](./presentation/cli/commands/<group>/README.md)
    - [Название действия](./presentation/cli/commands/<group>/<action>.md)
```

Не добавлять соседние presentation- или корневые разделы. Каждый актуальный
документ должен встречаться в навигации один раз; отсутствующие и удалённые
документы в неё не включать.

## Стабильные обозначения

Корневой контракт использует `<контекст>.presentation.cli`, группа добавляет
собственный сегмент, действие — отдельный сегмент действия. Общий вывод и модели
также получают отдельные смысловые сегменты. Имена файлов и классов реализации
не являются нормативными обозначениями.
