# Проверка документации CLI

## Структура и навигация

- CLI расположен одним поддеревом внутри `presentation/cli/`.
- Корневая команда, каждая группа и каждая конечная команда доступны из
  `SUMMARY.md` ровно один раз.
- Иерархия документов соответствует иерархии команд.
- Общие контракты имеют одного владельца и не скопированы в команды.
- Локальные ссылки и сборка документации проверены.
- Стабильные обозначения уникальны и не склеивают группу с действием.

## Корневой и групповой уровни

- Определены исполняемая команда, общий синтаксис и список подкоманд.
- Каждый уровень перечисляет свои возможности и описывает собственную справку.
- Для неполного вызова зафиксированы результат, поток и статус.
- Общие опции, defaults, короткие формы и взаимоисключаемость согласованы.
- Служебные команды не добавлены без требования.
- Краткие описания не перечисляют поля или внутренние шаги команд.

## Конечная команда

- Паспорт и полный синтаксис однозначны.
- Каждый аргумент и опция описаны отдельно.
- Отсутствие, пустое значение, повтор опции, неизвестный ввод и условные
  сочетания не оставлены на выбор реализации.
- Внешняя валидация отделена от бизнес-правил.
- CLI-вход полностью сопоставлен публичному application-входу.
- Application-результат полностью сопоставлен внешней CLI-модели.
- Публичные application-исходы преобразованы без обращения к domain.
- Форматы, поля, типы, порядок, потоки и статусы завершения определены.
- Повтор, корреляция и совместимость описаны.
- Открытые вопросы отражают реальные пробелы.

## Вывод и наблюдаемость

- Стабильный результат отделён от диагностического logging или явно описано
  другое принятое решение.
- Для каждого уровня подробности определено влияние на успех и ошибку.
- Quiet-режим не скрывает статус завершения.
- Внутреннее исключение и stack trace не попадают в стабильный результат.
- Logging-поля и события не дублируют общий observability-контракт.
- Не раскрываются секреты, необработанный ввод и чувствительные сведения.

## Примеры ответов

- Есть успешный ответ во всех различающихся форматах.
- Отсутствие успешного вывода явно показано, если оно является контрактом.
- Общая и специальная ошибочные модели имеют необходимые примеры.
- Каждый пример проверен по нормативной таблице полей.
- Разные форматы одного результата согласованы по значениям, составу и порядку.
- Текстовый вывод показан буквально, JSON синтаксически корректен.
- Пример ошибки не раскрывает внутренние детали.
- Примеры не вводят новых требований и не размножают однотипные случаи.

## Границы

- CLI-модель не названа application DTO и не передаётся наружу как внутренний
  контракт.
- Domain-ошибка не является непосредственным источником консольного результата.
- Не закреплены язык реализации, CLI-фреймворк, класс или библиотека.
- Код не использован как источник требований без разрешения.
