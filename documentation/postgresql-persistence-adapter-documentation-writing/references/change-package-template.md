# Шаблон пакета изменения

## Структура

```text
<sequence>-<meaningful-name>/
├── README.md
├── tables.md
├── indexes.md
└── rollback.md
```

Для малого изменения допустим один `README.md`, если он содержит все применимые
разделы. Нельзя объединять несколько логических изменений только ради одного
файла.

## Состав пакета в README

|Поле|Содержание|
|:---|:---|
|Идентификатор|Имя каталога|
|Статус|`planned`, `ready`, `applied`, `superseded`|
|Зависит от|Предыдущие логические пакеты|
|Назначение|Результат изменения|
|Yoyo migrations|Связанные идентификаторы либо `ещё не созданы`|
|Обновляет текущий снимок|Файлы актуальной схемы|

README также содержит локальную Mermaid ER-схему затронутых связей, preflight,
offline-порядок применения, post-migration проверки, maintenance estimate,
backfill, backup и риски.

## Дельта таблиц

|Таблица|Действие|Объект|До|После|Совместимость и данные|Статус|
|:---|:---|:---|:---|:---|:---|:---|

Для новой таблицы после дельты приводить полный будущий файл таблицы. Для
изменяемой таблицы не копировать весь итоговый состав: обновить его в `current`.

## Применение с остановкой сервиса

|Этап|Действие|Транзакционность|Проверка|Риск|
|:---|:---|:---|:---|:---|

Порядок: maintenance, остановка процессов, активные транзакции, preflight,
backup, миграция, post-check, запуск новой версии, readiness.

## Откат

Классифицировать изменение как полностью обратимое, обратимое до этапа,
обратимое с потерей данных или необратимое.

|Этап|Действие|Теряемые данные|Предусловие|Проверка результата|
|:---|:---|:---|:---|:---|

Указать окно отката, point of no return, восстановление backup и действия при
частично применённой миграции. После запуска новой версии учитывать записанные ею
данные до отката.
