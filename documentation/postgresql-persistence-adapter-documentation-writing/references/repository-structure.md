# Структура документации

Использовать каноническое размещение исходящего адаптера из общего скила
гексагональной документации:

```text
docs/
└── adapters/
    ├── README.md
    └── outgoing/
        ├── postgresql-persistence.md
        └── postgresql-persistence/
            ├── current/
            │   ├── README.md
            │   ├── companies/
            │   │   ├── companies.md
            │   │   ├── company-versions.md
            │   │   └── company-versions-published.md
            │   └── employees/
            │       ├── employees.md
            │       ├── employee-versions.md
            │       └── employee-versions-published.md
            └── changes/
                ├── 0001-initial-schema/
                │   ├── README.md
                │   ├── tables.md
                │   ├── indexes.md
                │   └── rollback.md
                └── 0002-next-change/
                    └── ...
```

`postgresql-persistence.md` — единственный канонический паспорт адаптера.
Одноимённый каталог содержит подробности физической схемы и не является вторым
паспортом.

Следовать существующему корню документации и механизму навигации репозитория, но
сохранять `adapters/outgoing`, имя в `kebab-case`, соседство паспорта и каталога.

## Текущий снимок (`current/README.md`)

Содержит:

1. назначение актуального снимка;
2. полную Mermaid `erDiagram` без колонок;
3. легенду;
4. навигационную таблицу `Таблица | Назначение | Документ`;
5. готовность и открытые вопросы.

Один файл таблицы описывает один физический объект. Группировать файлы по
агрегату или проекции, а не объединять их содержимое.

## История изменений (`changes`)

Один каталог — одно логическое изменение. Последовательный номер документации не
обязан совпадать с идентификатором yoyo. В manifest указывать связи с конкретными
миграциями только после разрешения читать или создавать их.

Применённые каталоги append-only. Исправление схемы создаёт новый пакет.

## Навигация

`docs/adapters/README.md` ссылается на паспорт. Паспорт ссылается на
`postgresql-persistence/current/README.md` и индекс `changes`. Каждый файл
таблицы и пакета достижим из соответствующего README и основной навигации
репозитория.

Пути и имена файлов остаются техническими. Видимые заголовки и подписи ссылок в
README и `SUMMARY.md` писать на языке документа. В русскоязычной документации
использовать «Хранилище PostgreSQL», «Текущий снимок» и «История изменений».

Для mdBook включать в `SUMMARY.md` каждый файл таблицы и пакета изменений, иначе
страница не попадёт в собранную книгу. В обычных Markdown-документах ссылаться на
раздел с `README.md` через каталог с завершающим `/`: mdBook публикует такой файл
как `index.html`, а ссылка непосредственно на `README.md` может превратиться в
несуществующий `README.html`.
