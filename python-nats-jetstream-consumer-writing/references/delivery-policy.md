# Политика доставки JetStream consumer

## Модель решения

Политика получает публичный результат или ошибку application-операции и возвращает одно из действий:

```text
ACK
NAK(delay)
TERM
```

Конкретная таблица определяется требованиями. Не классифицируй ошибки по именам domain- или infrastructure-классов.

## Безопасные правила

| Ситуация | Правило |
|---|---|
| Операция завершилась успешно | ACK |
| Сообщение уже идемпотентно обработано | ACK |
| Временная публичная ошибка | NAK с согласованной задержкой |
| Постоянно некорректный транспортный контракт | TERM или DLQ согласно требованиям |
| Неизвестная ошибка | Повтор в пределах broker policy, не автоматический TERM |
| Отмена задачи | Не отправлять итоговое подтверждение |
| Ошибка ACK | Считать подтверждение неопределённым |

## Отличие TERM от DLQ

`TERM` прекращает повторную доставку текущему consumer. Он не переносит сообщение в отдельное хранилище. DLQ требует отдельной успешной записи, после которой исходное сообщение можно окончательно подтвердить.
