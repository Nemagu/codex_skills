# Фикстуры и параметризация

## Размещение фикстуры

1. Для одного теста создай данные локально.
2. Для нескольких тестов одного модуля используй фикстуру в этом модуле.
3. Для нескольких модулей перенеси фикстуру в ближайший общий `conftest.py`.
4. Для вариантов объекта предоставь factory-функцию из фикстуры.
5. При обнаружении дублирующей фабрики перенеси её на минимально высокий общий
   уровень.

Не создавай общий реестр фикстур заранее и не расширяй scope ради удобства.

## Фабрика

```python
@pytest.fixture
def item_factory():
    def create(*, name: str = "item"):
        return Item(name=name)

    return create
```

- Используй именованные параметры.
- Значения по умолчанию формируют валидный объект.
- Изменяй в тесте только значимые для сценария поля.
- Не добавляй неуправляемую случайность.

## Параметризация

```python
@pytest.mark.parametrize(
    ("raw_value", "expected"),
    [
        ("first", "first"),
        (" second ", "second"),
    ],
    ids=["unchanged", "trimmed"],
)
def test_normalize(raw_value: str, expected: str) -> None:
    assert normalize(raw_value) == expected
```

Используй один parametrized-тест, когда различаются только вход и ожидание, а
последовательность действий остаётся одинаковой.

Для сложных случаев:

```python
@dataclass(frozen=True, slots=True)
class Case:
    raw_value: str
    expected: str
```

Не помещай в case-объект скрытую процедуру проверки.
