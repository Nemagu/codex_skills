# Чеклист адаптера хранения

## Контракт и транзакция

- Публичные методы реализуют существующий порт.
- DB-типы не выходят наружу.
- Приватные helpers устраняют реальное дублирование.
- Use case получает фабрику, создающую новый UoW.
- UoW единолично завершает транзакцию.
- Репозитории используют одно соединение UoW.
- Sync/async соответствует порту.
- UoW нельзя повторно или конкурентно использовать.

## Запись и чтение

- Одиночный `save` использует `execute`.
- Batch-сохранение использует `executemany`.
- Пустая пачка не вызывает SQL.
- Доменный ID и значимое время переданы вызывающей стороной.
- Версия и optimistic locking соответствуют контракту.
- Partial update различает `UNSET`, `None` и значение.
- Mapping создаёт domain через фабрику либо DTO порта.
- Пагинация детерминирована; нулевой count исключает второй запрос.
- Batch-чтение не создаёт N+1.
- Scope включён в каждый требуемый запрос.

## Ошибки и SQL

- DB-методы используют `@handle_postgres_errors`.
- Причина сохранена в `wrap_error`.
- Use case не анализирует psycopg.
- Constraint-категории заданы приватной явной картой.
- SQL не использует f-строки и `SELECT *`.
- Данные параметризованы.
- Идентификаторы собраны через `Identifier`.
- Пробрасываемая ошибка не логируется в адаптере.
- Retry повторяет всю операцию с новым UoW.

## Менеджер подключений

- Async pool открывается и закрывается явно.
- Pool создаётся один раз на worker.
- Ожидание соединения ограничено timeout.
- Соединение возвращается чистым либо отбрасывается.
- Session state не протекает между UoW.
- Отмена задачи не маскируется.

## Миграции

- Схема показана и подтверждена пользователем.
- Перезапись файлов разрешена явно.
- Индексы и уникальность согласованы отдельно.
- Разрушительные операции подтверждены.
- Dependencies yoyo заданы явно.
- Apply и rollback реализованы.
- Миграция проверена `apply → rollback → apply`.
- Имена и типы совпадают с persistence-кодом.

## Тесты

- Mapper-ы, параметры, UoW и классификация ошибок покрыты unit-тестами.
- SQL и атомарность проверены integration-тестами на PostgreSQL.
- Миграции применяются только через yoyo.
- Проверены только предусмотренные портом операции.
