# Безопасное обеспечение топологии publisher

## Алгоритм

1. Сгруппируй требуемые subject по stream.
2. Проверь обязательные поля и конфликты маршрутов локально.
3. Получи `stream_info`.
4. Если stream отсутствует, создай его из явно заданных управляемых параметров.
5. Если stream существует, сравни только управляемые параметры.
6. Добавь отсутствующие subject в полученный `StreamConfig`.
7. Не удаляй лишние subject и не заменяй конфигурацию новой моделью с defaults.
8. После конкурентного конфликта ограниченно перечитай состояние.
9. Считай подготовку успешной только при соответствии итогового состояния.

## Конкурентный startup

Допустим следующий ограниченный сценарий:

1. два экземпляра одновременно не находят stream;
2. один успешно создаёт его;
3. второй получает конфликт создания;
4. второй повторно читает stream;
5. если итог соответствует требованиям, startup успешен;
6. иначе возвращается ошибка топологии.

Не создавай бесконечный retry и не удаляй объект для повторного создания.
