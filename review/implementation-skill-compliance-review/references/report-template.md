# Формат отчёта по implementation-скилам

Использовать этот шаблон для `.review/skill-compliance.md`. Сохранять файл
самодостаточным: исправляющий агент должен понимать поля без загрузки скила.

```markdown
# Соответствие реализации прикладным скилам

## Правила оформления замечаний

### Статус

Допустимы только следующие статусы:

- `Актуально` — нарушение подтверждено и ещё не устранено;
- `Исправлено` — необходимые изменения внесены и относящиеся к замечанию проверки
  успешно выполнены;
- `Требует согласования` — расхождение подтверждено, но ожидаемое поведение или
  способ устранения нельзя определить без решения пользователя.

Нельзя вводить другие статусы или изменять их написание.

### Приоритет

Допустимы только следующие приоритеты:

- `Высокий` — нарушение может привести к неправильному публичному поведению,
  потере данных, нарушению согласованности, безопасности или lifecycle процесса;
- `Средний` — обязательное правило нарушено, но влияние локально и не создаёт
  непосредственного критического риска;
- `Низкий` — нарушена рекомендация либо обязательное нарушение имеет небольшое
  практическое влияние.

Нельзя вводить другие приоритеты или изменять их написание. Нарушение рекомендации
всегда имеет приоритет `Низкий`. Для требования приоритет определяется по
практическому влиянию, а не по объёму необходимых исправлений.

### Тип правила

Допустимы только следующие типы правила:

- `Требование` — обязательное правило скила;
- `Рекомендация` — явно необязательный предпочтительный подход, от которого
  допустимо отступить с осознанным обоснованием.

Нельзя вводить другие типы правила или изменять их написание.
Если источник не позволяет однозначно определить тип правила, замечание получает
статус `Требует согласования`.

### Переходы статусов

- Проверяющий создаёт доказанное замечание со статусом `Актуально`, а при
  необходимости решения пользователя — `Требует согласования`.
- Исправляющий агент берёт в работу `Актуально`, вносит изменение и выполняет
  относящиеся к замечанию проверки. Только после их успеха он меняет статус на
  `Исправлено`.
- Для `Требует согласования` сначала заменить `Требуется решение.` в блоке
  `Решение` на принятое решение и перевести замечание в `Актуально`. После
  реализации решения и успешных проверок перевести его в `Исправлено`.
- При повторном аудите проверяющий оставляет `Исправлено`, если нарушение не
  воспроизводится, и возвращает `Актуально`, если оно сохранилось или появилось
  снова.
- Начало работы, изменение кода без проверки или заполнение блока `Решение` сами
  по себе не означают `Исправлено`.

### Работа с решением и полями

- Для нового `Актуально` проверяющий пишет в `Решение`: `Требуется исправление.`
- Для нового `Требует согласования` проверяющий пишет в `Решение`:
  `Требуется решение.` и не выбирает вариант самостоятельно.
- Исправляющий агент заменяет шаблон фактическим описанием внесённого изменения.
- После исправления сохранять ID, приоритет и тип правила. Исправляющий агент не
  меняет их; проверяющий может скорректировать классификацию только по новым
  доказательствам.
- Не удалять исправленные замечания без явной просьбы пользователя.
```

## Правила замечаний

- Использовать идентификаторы `SKILL-001`, `SKILL-002` и далее.
- Сохранять ID при изменении статуса, пути, строки и заголовка.
- Назначать новому замечанию номер после максимального существующего; не
  использовать освободившийся номер повторно.
- После явной полной очистки начинать с `SKILL-001`.
- Формулировать заголовок как проблему, а не решение.
- Описывать одну независимо исправимую первопричину в одном замечании.
- Для статуса `Требует согласования` добавлять обязательный блок
  `**Что требуется согласовать.**` с конкретным вопросом.
- Добавлять обязательный блок `**Решение.**` в каждое замечание. Для нового
  `Актуально` писать `Требуется исправление.`, для нового
  `Требует согласования` — `Требуется решение.`. Не предлагать решение от имени
  проверяющего.
- Для `Исправлено` заменять шаблон кратким описанием фактически внесённого
  изменения; не оставлять шаблонную фразу.
- Разрешать необязательные пользовательские блоки
  `**Комментарий к исправлению.**` и другие пояснения.
- Сохранять неизвестные поля и содержательный пользовательский текст.
- Сохранять исходные приоритет и тип правила после исправления.
- Сортировать замечания по приоритету `Высокий`, `Средний`, `Низкий`, затем по
  расположению; не перенумеровывать при сортировке.

## Обновление файла

- Создавать новые замечания со статусом `Актуально` либо, при доказанном конфликте,
  `Требует согласования`.
- Разрешать исправляющему агенту или человеку ставить `Исправлено` только после
  внесения изменений и успешных относящихся проверок.
- При повторном аудите оставлять `Исправлено`, если нарушение не воспроизводится,
  и возвращать `Актуально`, если оно сохранилось или появилось снова.
- Переводить `Требует согласования` сначала в `Актуально` после принятия решения и
  только затем в `Исправлено` после реализации решения.
- Сопоставлять замечания по источнику правила, первопричине и основному компоненту,
  а не только по строке или заголовку.
- При объединении дублей сохранять более ранний ID и все пользовательские записи;
  перечислять поглощённые ID в блоке `**Объединённые замечания.**`.
- При разделении сохранять исходный ID у основной проблемы, новым независимым
  проблемам назначать новые ID.
- При полной проверке пересматривать все замечания, но не удалять `Исправлено` без
  явной просьбы.
- При ограниченной проверке не менять замечания вне области.
- Очищать исправленные замечания только по явной просьбе пользователя.
- Если замечаний нет, писать `Замечаний нет.`, сохраняя область и ограничения.
