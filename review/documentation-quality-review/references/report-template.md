# Формат отчёта о качестве документации

Использовать этот шаблон для `.review/documentation-quality.md`. Сохранять файл
самодостаточным: пользователь и исправляющий агент должны понимать поля без
загрузки проверочного скила.

```markdown
# Качество документации

## Правила оформления замечаний

### Статус

Допустимы только следующие статусы:

- `Актуально` — проблема подтверждена, её устранение однозначно и ещё не выполнено;
- `Исправлено` — документация изменена и относящиеся проверки выполнены;
- `Требует согласования` — проблема подтверждена, но ожидаемое требование или
  способ устранения требует решения пользователя.

Нельзя вводить другие статусы или изменять их написание.

### Приоритет

Допустимы только следующие приоритеты:

- `Высокий` — документация не позволяет реализовать публичное или системно
  значимое поведение без нового решения либо задаёт несовместимые контракты;
- `Средний` — проблема блокирует отдельную часть реализации или создаёт
  существенный риск разного понимания;
- `Низкий` — проблема локальна, не меняет наблюдаемое поведение либо нарушает
  рекомендацию.

Нельзя вводить другие приоритеты или изменять их написание. Нарушение рекомендации
всегда имеет приоритет `Низкий`.

### Тип правила

Допустимы только следующие типы правила:

- `Требование` — обязательное правило скила, репозитория или нормативного
  документа;
- `Рекомендация` — явно необязательный предпочтительный подход.

Нельзя вводить другие типы правила или изменять их написание. Если обязательность
найденного правила нельзя определить, замечание получает статус
`Требует согласования`.

### Класс

Допустимы только следующие классы:

- `Противоречие`;
- `Пробел`;
- `Неоднозначность`;
- `Нарушение структуры`;
- `Нарушение владения`;
- `Несогласованная ссылка`;
- `Нарушение рекомендации`.

Нельзя вводить другие классы или изменять их написание.

### Переходы статусов

- Проверяющий создаёт замечание со статусом `Актуально`, когда исправление
  однозначно, и `Требует согласования`, когда нужен продуктовый или архитектурный
  выбор.
- Исправляющий агент берёт в работу `Актуально`, изменяет документацию и выполняет
  относящиеся проверки. Только после их успеха он меняет статус на `Исправлено`.
- Для `Требует согласования` сначала заменить `Требуется решение.` в блоке
  `Решение` на принятое решение и перевести замечание в `Актуально`. После
  внесения решения в нормативную документацию и повторной проверки перевести его
  в `Исправлено`.
- При повторном аудите проверяющий оставляет `Исправлено`, если проблема не
  воспроизводится, и возвращает `Актуально`, если она сохранилась или появилась
  снова.
- Начало работы, изменение документа без проверки или заполнение блока `Решение`
  сами по себе не означают `Исправлено`.

### Работа с решением и полями

- Для нового `Актуально` проверяющий пишет в `Решение`: `Требуется исправление.`
- Для нового `Требует согласования` проверяющий пишет в `Решение`:
  `Требуется решение.` и не принимает решение самостоятельно.
- Исправляющий агент заменяет шаблон фактическим описанием внесённого изменения.
- После исправления сохранять ID, приоритет, тип правила и класс. Исправляющий
  агент не меняет их; проверяющий может скорректировать классификацию только по
  новым доказательствам.
- Не удалять исправленные замечания без явной просьбы пользователя.

## Проверено

- **Режим:** `<полная проверка | ограниченная проверка>`
- **Область:** `<пути, разделы или комплект документов>`
- **Основание области:** `<запрос пользователя>`
- **Документы:** `<перечень или правило отбора>`
- **Применимые скилы:**
  - `<имя скила>`
- **Выполненные проверки:**
  - `<локальная или междокументная проверка>` — `<результат>`
- **Исключено:** `<черновики, примеры, области или отсутствует>`

## Замечания

### DOCQ-001 — Краткое название проблемы

- **Статус:** `Требует согласования`
- **Приоритет:** `Высокий`
- **Тип правила:** `Требование`
- **Класс:** `Пробел`
- **Источник проверки:** `<скил, раздел, пункт или правило репозитория>`
- **Документация:** `<файл и раздел; при необходимости несколько источников>`

**Что обнаружено.**
Конкретная проблема и достаточные доказательства.

**Что требуется.**
Какое свойство должна иметь документация без придумывания отсутствующего решения.

**Что требуется согласовать.**
Конкретный вопрос, если статус — `Требует согласования`.

**Решение.**
Требуется решение.

**Почему это важно.**
Влияние на реализацию, согласованность или понимание контракта.

## Ограничения проверки

- `<что и почему не проверено либо "Ограничений нет.">`
```

## Правила замечаний

- Использовать идентификаторы `DOCQ-001`, `DOCQ-002` и далее.
- Сохранять ID при изменении статуса, пути, строки и заголовка.
- Назначать новому замечанию номер после максимального существующего; не
  использовать освободившийся номер повторно.
- После явной полной очистки начинать с `DOCQ-001`.
- Формулировать заголовок как проблему, а не решение.
- Описывать одну независимо исправимую первопричину в одном замечании.
- Для противоречия перечислять все конфликтующие места документации.
- Для пробела указывать место определения требования или ожидаемой ссылки.
- Добавлять `**Что требуется согласовать.**` только при одноимённом статусе.
- Добавлять обязательный блок `**Решение.**` в каждое замечание. Для нового
  `Актуально` писать `Требуется исправление.`, для нового
  `Требует согласования` — `Требуется решение.`.
- Не предлагать и не выбирать решение от имени проверяющего. Возможные варианты
  перечислять только в `Что требуется согласовать`.
- Для `Исправлено` заменять шаблон кратким описанием фактически внесённого
  изменения; не оставлять шаблонную фразу.
- Сохранять заполненное пользователем или исправляющим агентом решение,
  неизвестные поля и содержательные комментарии.
- Сохранять исходные приоритет, тип правила и класс после исправления.
- Сортировать замечания по приоритету `Высокий`, `Средний`, `Низкий`, затем по
  расположению; не перенумеровывать при сортировке.

## Обновление файла

- Создавать замечание со статусом `Актуально`, когда устранение однозначно, и
  `Требует согласования`, когда нужен продуктовый или архитектурный выбор.
- После заполнения `Решение` переводить `Требует согласования` в `Актуально`, если
  решение ещё не внесено в нормативную документацию.
- Переводить в `Исправлено` только после внесения решения в документацию и
  повторной проверки.
- Возвращать `Исправлено` в `Актуально`, если проблема сохранилась или появилась
  снова.
- Сопоставлять замечания по источнику проверки, первопричине и затронутому
  контракту, а не только по строке или заголовку.
- При объединении дублей сохранять более ранний ID и все пользовательские записи;
  перечислять поглощённые ID в блоке `**Объединённые замечания.**`.
- При разделении сохранять исходный ID у основной проблемы, новым независимым
  проблемам назначать новые ID.
- При полной проверке пересматривать все замечания, но не удалять `Исправлено` без
  явной просьбы.
- При ограниченной проверке не менять замечания вне области.
- Очищать исправленные замечания только по явной просьбе пользователя.
- Если замечаний нет, писать `Замечаний нет.`, сохраняя область и ограничения.
