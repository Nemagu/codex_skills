# Интеграционная инфраструктура

## Режимы

| Режим | Владение lifecycle | Источник подключения |
|---|---|---|
| Локальный | Тестовая session-фикстура | Созданная ею конфигурация |
| Внешний | Внешнее окружение | Переменные окружения |

Имя переключателя и переменных является контрактом проекта, а не общего скила.

## Session runtime

Одна session-scoped фикстура:

1. определяет выбранный режим;
2. создаёт уникальный runtime ID;
3. готовит минимальный контекст подключения;
4. в локальном режиме запускает subprocess;
5. активно проверяет готовность с timeout;
6. передаёт контекст технологическим фикстурам;
7. в `finally` освобождает только принадлежащие ей ресурсы.

Если startup завершился частично, cleanup всё равно выполняется.

## Изоляция локального режима

- Создавай временные файлы вне репозитория.
- Используй отдельный каталог одного прогона.
- Добавляй runtime ID к именам файлов, subprocess-проекта и глобальных ресурсов.
- Подбирай порты динамически.
- Не используй общий контейнерный namespace.
- Не записывай секреты в отслеживаемые файлы.
- Удаляй созданные файлы после остановки subprocess.

## Внешний режим

- Не запускай и не останавливай инфраструктуру.
- Не применяй необратимые административные изменения без отдельного контракта.
- Получай обязательные сведения из environment.
- Отсутствующее значение обрабатывай явно согласно правилам репозитория.
- Проверяй доступность до выполнения тестов.
- Используй уникальный namespace ресурсов, если технология имеет глобальные имена.

## Технологические операции

Общий runtime не определяет:

- команду запуска и состав сервисов;
- способ проверки готовности конкретной технологии;
- применение схемы или миграций;
- создание stream, topic и других объектов;
- очистку данных между тестами;
- формат connection settings.

Эти действия выполняют технологические фикстуры штатными средствами выбранных
инструментов.

## Параллельные прогоны

Два одновременных прогона не должны разделять:

- container project name;
- временные файлы;
- опубликованные порты;
- базы или схемы без изоляции;
- глобальные имена брокера;
- изменяемые каталоги.

Cleanup одного прогона не должен удалять ресурсы другого.
