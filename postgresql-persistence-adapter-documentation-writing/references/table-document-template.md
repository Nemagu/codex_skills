```markdown
## Колонки

|Колонка|Тип PostgreSQL|NULL|Default|Ключи и ссылки|Смысл|
|:---|:---|:---|:---|:---|:---|

|:---|:---|:---|:---|:---|

|Имя|Ключи или выражения|Тип|Уникальный|Predicate|Источник|Причина|Цена и пересечения|EXPLAIN|

|:---|:---|:---|:---|

## Открытые вопросы
```

## Правила

- Одна физическая таблица — один файл и одна таблица колонок.
- Не копировать `CREATE TABLE` или ORM-модель вместо аналитической схемы.
- Для отсутствующего default писать `Нет`, для SQL `NULL` явно писать `NULL`.
- Указывать составной порядок PK/UQ/индекса без перестановки.
- В связях различать входящие и исходящие FK.
- Для массива идентификаторов без FK явно описывать владельца целостности.
- Для каждого индекса указывать конкретную операцию и причину.
- Constraint-backed индекс не дублировать как явно созданный.
- Отложенные ограничения и индексы держать в открытых вопросах, не в нормативной
  таблице.
