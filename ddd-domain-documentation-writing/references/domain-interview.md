# Интервью по доменной модели

## Общий порядок

До создания документа выяснить владельца объекта, его назначение и границу.
Задавать не более трёх связанных вопросов за раз. Сначала уточнять решения, которые
меняют владельца, состав объекта или смысл следующих вопросов.

Не считать код источником отсутствующих требований. Можно изучать существующую
документацию и согласованную терминологию. Предлагать рекомендацию с аргументом,
оставляя итоговое решение пользователю.

## Агрегат

Выяснить корень и принадлежащие сущности, поля и бизнес-типы, жизненный цикл,
инварианты, операции поведения, ожидаемые доменные отказы, права и порождаемые
события. Отдельно проверить, какие правила требуют сведений вне агрегата.

## Value object и доменный сервис

Для value object выяснить смысл, состав, ограничения, нормализацию и равенство.
Для доменного сервиса определить обеспечиваемый инвариант, почему он не принадлежит
одному агрегату, необходимые сведения и ожидаемые отказы.

## Проекция

Выяснить владельца исходных данных, минимальный локальный снимок, версию, правила
принятия повторных и устаревших данных, допустимую свежесть и использование внутри
контекста.

## Доменные события

Выяснить свершившийся факт, агрегат-источник, момент возникновения, состав снимка,
область распространения и связь события с версией агрегата. Не обсуждать свойства
конкретного транспорта как часть доменного события.

## Открытые вопросы

Каждый создаваемый документ завершать разделом `## Открытые вопросы`. Если
нерешённых вопросов нет, писать `Открытых вопросов нет.`.
