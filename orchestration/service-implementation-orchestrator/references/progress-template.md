# Реестр прогресса реализации

Использовать шаблон для `.orchestration/implementation-progress.md`. Файл не
является нормативной документацией и не должен добавляться в Git. Если отдельной
строки `.orchestration/` нет в корневом `.gitignore` целевого проекта, предложить
пользователю добавить её. Не изменять `.gitignore` без согласия. Поддерживать файл
самодостаточным и актуальным после каждого этапа.

```markdown
# Прогресс реализации

## Статусы

Допустимы только следующие статусы элементов:

- `Не начато` — элемент входит в область, работа ещё не начата;
- `В работе` — элемент реализуется или проверяется сейчас;
- `Выполнено` — все артефакты элемента созданы и относящиеся проверки успешны;
- `Заблокировано` — продолжение требует настоящего внешнего решения или ресурса;
- `Не требуется` — элемент рассмотрен и доказанно не входит в заявленную область.

Нельзя вводить другие статусы или изменять их написание.
```

## Правила ведения

- Назначать элементам стабильные ID `IMP-001`, `IMP-002` и далее.
- Не удалять незавершённый элемент ради формального выполнения DoD.
- Обновлять строку после каждого изменения статуса и проверки.
- Не ставить `Выполнено` без указанного успешного доказательства.
- При выявлении нового требуемого элемента добавлять его в план и зависимости.
- Сохранять решения пользователя, исходные изменения и явные исключения.
- После снятия блокера менять статус затронутых элементов и продолжать работу.
- Держать `Следующий шаг` непустым, пока Definition of Done не выполнен.
