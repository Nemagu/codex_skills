# Регламент `SUMMARY.md`

## Владение

Главный скил владеет корневым порядком и собирает глобальное дерево навигации.
Специализированный скил формирует только поддерево своего архитектурного слота и
не переставляет соседние разделы.

## Корневой порядок

Включать только существующие разделы в следующем порядке:

1. введение;
2. бизнес-контекст;
3. доменная модель;
4. прикладной слой;
5. презентационный слой;
6. исходящие внешние контракты;
7. паспорта адаптеров.

Внутри presentation использовать порядок: HTTP API, входящие сообщения, фоновые
процессы. Внутри adapters: входящие, затем исходящие.

## Правила дерева

- Индексный `README.md` размещать перед дочерними страницами.
- Иерархия должна повторять архитектурное владение и каноническую структуру
  каталогов.
- Каждый содержательный документ включать ровно один раз.
- Не включать отсутствующий или пустой раздел.
- Не использовать ссылку на дочерний документ как замену индексной странице
  самостоятельного раздела.
- При большом числе страниц группировать их под локальными индексами, а не
  создавать плоский список верхнего уровня.
- Подписи писать на языке документации; технические пути сохранять на английском.
- После перемещения удалять старую ссылку и проверять все относительные пути.

## Фрагмент специализированного раздела

Специализированный скил возвращает фрагмент, начинающийся с индексной страницы
назначенного слота:

```markdown
- [Название раздела](./slot/README.md)
  - [Группа](./slot/group/README.md)
    - [Документ](./slot/group/document.md)
```

Главный скил встраивает фрагмент в каноническую позицию без изменения его
внутреннего порядка, если тот не нарушает глобальные правила.

## Проверка

- Все пути существуют и разрешаются относительно `SUMMARY.md`.
- Все содержательные Markdown-файлы достижимы из навигации.
- Дубликаты ссылок отсутствуют.
- Индекс предшествует дочерним страницам.
- Корневые разделы расположены в каноническом порядке.
- Видимые подписи соответствуют языку документации.
