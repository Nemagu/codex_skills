# Семантика периодической задачи

## Режимы

| Режим | Следующий запуск |
|---|---|
| `fixed-delay` | Через заданный интервал после полного завершения операции |
| `fixed-rate` | По монотонной временной сетке независимо от длительности операции |

Для `fixed-rate` пропущенные моменты не образуют очередь. После долгой операции выбирается ближайший будущий момент.

## Форма зависимости

```python
@dataclass(frozen=True, slots=True)
class PeriodicTaskOptions:
    schedule_mode: ScheduleMode
    interval_seconds: float
    operation_timeout_seconds: float | None


type ApplicationOperation = Callable[[], Awaitable[OperationResult | None]]
```

Имена и тип результата адаптируй к проекту. Не добавляй в общий контракт предметные поля.

## Обязательные тесты

- fixed-delay отсчитывается после операции;
- fixed-rate сохраняет временную сетку;
- пропущенные fixed-rate интервалы не догоняются;
- повторный запуск не начинается до завершения предыдущего;
- stop event прерывает ожидание;
- no-work считается успехом;
- startup delay и jitter работают только при включении;
- ожидаемая, повторяемая и фатальная ошибки следуют политике;
- timeout отменяет итерацию;
- результат не влияет на расписание.
