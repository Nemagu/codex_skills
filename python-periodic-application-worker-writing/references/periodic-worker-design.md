# Семантика периодической задачи

## Режимы

| Режим | Следующий запуск |
|---|---|
| `fixed-delay` | Через заданный интервал после полного завершения операции |
| `fixed-rate` | По монотонной временной сетке независимо от длительности операции |
| Result-aware delay | Сразу или через заданную задержку согласно варианту публичного результата |

Для `fixed-rate` пропущенные моменты не образуют очередь. После долгой операции выбирается ближайший будущий момент.

## Форма зависимости

```python
@dataclass(frozen=True, slots=True)
class PeriodicTaskOptions:
    schedule_mode: ScheduleMode
    interval_ms: int
    operation_timeout_ms: int | None


type ApplicationOperation = Callable[[], Awaitable[OperationResult | None]]
```

Конкретный класс называть `<OperationName>Task`, публичный цикл — `run()`. Имена
options и результата адаптировать к операции. Единицу всегда указывать в имени
поля; в секунды преобразовывать только перед вызовом `asyncio`.
Не добавляй в общий контракт предметные поля.

Callable задачи является долгоживущим: он сам выполняет цикл до установки stop
event. Для нескольких задач runtime запускает несколько таких callable; общий
цикл по списку задач не создаётся.

Для result-aware delay задай исчерпывающее сопоставление всех вариантов
DTO-перечисления с немедленным запуском или задержкой. Не используй fallback для
неизвестного варианта: изменение публичного перечисления должно потребовать
явного обновления и теста задачи.

## Обязательные тесты

- fixed-delay отсчитывается после операции;
- fixed-rate сохраняет временную сетку;
- пропущенные fixed-rate интервалы не догоняются;
- повторный запуск не начинается до завершения предыдущего;
- stop event прерывает ожидание;
- no-work считается успехом;
- startup delay и jitter работают только при включении;
- ожидаемая, повторяемая и фатальная ошибки следуют политике;
- timeout отменяет итерацию;
- для обычных fixed-delay/fixed-rate результат не влияет на расписание;
- для result-aware delay каждый вариант результата даёт согласованную задержку;
- неизвестный вариант результата не обрабатывается неявным fallback;
- каждая задача самостоятельно выполняет свой цикл до остановки.
