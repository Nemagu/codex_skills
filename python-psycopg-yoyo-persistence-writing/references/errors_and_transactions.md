# Ошибки и конкурентность

## Декоратор psycopg

Использовать параметризованный декоратор на приватной DB-операции:

```python
@handle_postgres_errors(action="сохранение арендатора")
async def _update(...) -> None:
    ...
```

Декоратор:

- поддерживает используемый sync/async-режим;
- сохраняет метаданные через `functools.wraps`;
- перехватывает только ожидаемые `psycopg.Error`;
- не оборачивает `AppPortError` повторно;
- создаёт ошибку через именованные аргументы;
- сохраняет причину в `wrap_error`;
- использует `raise ... from error`;
- не логирует.

Доменные ошибки фабрики обрабатывать отдельно через `@handle_domain_errors`.

## Различимые причины

Если порт различает конфликт или недоступность, помещать в безопасное `data`
стабильную application-категорию. Use case анализирует категорию, но не тип
psycopg в `wrap_error`.

Известные constraint names сопоставлять с категориями в приватной карте. Не
определять смысл по тексту ошибки. SQLSTATE использовать только как технический
класс. Неизвестное ограничение — общая ошибка порта.

Не передавать SQLSTATE, constraint name, SQL, параметры, credentials и
персональные данные.

## Повторные попытки

- Не повторять statement после deadlock, serialization failure или потери связи.
- Считать транзакцию непригодной до rollback.
- При заданном retry повторять всю application-операцию с новым UoW.
- Явно задавать категории, число попыток, backoff и deadline.
- Не повторять неидемпотентную внешнюю операцию автоматически.
- Логировать итог после исчерпания, а не каждую обработанную попытку.

## Отмена

- Не преобразовывать `CancelledError` в `AppPortError`.
- Попытаться ограниченно завершить rollback и cleanup.
- Не использовать неограниченный `shield`.
- Не возвращать неочищенное соединение как здоровое.
- После cleanup повторно распространить отмену.
