# Единица работы PostgreSQL

## Обязательная фабрика

Транзакционный use case получает `UnitOfWorkFactory`, а не экземпляр UoW.
Фабрика:

- является stateless и пригодна для долгого хранения в use case;
- возвращает новый UoW при каждом вызове;
- не получает connection до входа UoW;
- не возвращает ранее использованный экземпляр;
- создаёт новый UoW для каждой retry-попытки.

Query без транзакционной потребности использует read-порт напрямую.

## Жизненный цикл UoW

UoW:

1. Запрещает повторный или конкурентный вход.
2. Арендует соединение у connection manager.
3. Входит в явный `connection.transaction()`.
4. Создаёт неизменяемые repository-группы на одном соединении.
5. При успехе завершает transaction context commit.
6. При исключении завершает его rollback.
7. Возвращает или отбрасывает соединение.
8. Очищает connection, transaction context и группы.

Доступ к группам до входа и после выхода запрещён. Частично неуспешный
`__aenter__` освобождает уже полученные ресурсы.

## Единственный владелец завершения

Контекст `pool.connection()` psycopg сам завершает открытую транзакцию. Не
использовать его внутри UoW вместе с отдельным transaction context. Connection
manager предоставляет lease через `getconn`/`putconn` или эквивалент, а UoW
единолично владеет `connection.transaction()`.

Не выполнять второй commit/rollback при повторном cleanup. Ошибку
commit/rollback/аренды преобразовывать в `AppPortError`, сохраняя цепочку.

## Группы репозиториев

Создавать группу один раз при входе:

```python
@dataclass(frozen=True, slots=True)
class TenantRepositories:
    tenants: TenantRepository
    versions: TenantVersionRepository
```

- Аннотировать поля application-интерфейсами.
- Передавать реализациям одно соединение.
- Не создавать группы лениво при каждом property access.
- Не хранить connection отдельным публичным полем группы.
- Не выполнять SQL при создании группы.

## Дополнительные режимы

Isolation level, read-only, deferrable, nested UoW и savepoints реализовывать
только по контракту. Savepoint не считать вложенным UoW без явной семантики
частичного отката.

## Проверка

- Новый экземпляр на каждый вызов фабрики.
- Успешный commit и rollback при исключении.
- Cleanup при частично упавшем входе.
- Запрет доступа вне контекста и повторного входа.
- Отсутствие общего состояния у конкурентных use case.
- Реальная атомарность нескольких репозиториев на PostgreSQL.
