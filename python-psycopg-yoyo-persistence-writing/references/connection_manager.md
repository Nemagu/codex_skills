# Менеджер подключений и пул

## Ответственность

Connection manager:

- создаёт и закрывает sync/async pool;
- арендует и возвращает соединение без скрытой application-транзакции;
- задаёт согласованные connection kwargs и `row_factory=dict_row`;
- проверяет готовность pool в lifecycle worker-а;
- не определяет успех application-операции.

Настройки DSN, размеров и timeout получать из конфигурационного адаптера. Не
хранить credentials и локальные параметры в коде.

## Жизненный цикл асинхронного пула

- Создавать `AsyncConnectionPool` с `open=False`.
- Явно вызывать `open()` в lifecycle worker-а.
- Вызывать `wait()` с ограниченным timeout, если БД обязательна для готовности.
- Сначала остановить приём новых операций, затем закрыть pool.
- Не создавать pool на repository/UoW и не закрывать его оттуда.
- `PoolTimeout` классифицировать как недоступность порта.

## Аренда

- Использовать узкий типизированный `Protocol` вместо зависимости UoW от всего
  API pool.
- Возвращать connection во всех ветках.
- Не отдавать его за пределы UoW/standalone read-вызова.
- Не хранить connection в глобальном mutable state.
- Не разделять соединение между независимыми конкурентными UoW.
- Не возвращать повреждённое либо неочищенное соединение как здоровое.

## Очистка состояния

- Не оставлять открытую или failed transaction.
- Session-level `search_path`, role, timezone и параметры восстанавливать.
- Предпочитать `SET LOCAL` для транзакционных настроек.
- Настраивать reset/check callback централизованно, если состояние меняется.
- Не допускать утечки server-side cursor и неожиданных session-настроек.

Учитывать, что `pool.connection()` автоматически применяет семантику
commit/rollback. Для UoW использовать lease без этого поведения.
