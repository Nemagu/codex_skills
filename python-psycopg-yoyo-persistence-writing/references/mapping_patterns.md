# Преобразование моделей

## Тип результата

- Агрегат или доменную проекцию восстанавливать в `_model_to_domain`.
- DTO порта создавать в `_model_to_dto`.
- Не загружать агрегат, если контракту достаточно DTO.
- Не возвращать `DictRow` и другие DB-типы.

## Восстановление домена

`_model_to_domain`:

- использует только предусмотренную доменную фабрику;
- не вызывает конструктор вместо фабрики;
- не изменяет приватные поля агрегата;
- оборачивается проектным `@handle_domain_errors`;
- преобразует примитивы в объекты-значения;
- передаёт все данные состояния и версии;
- не исправляет повреждённые данные и не подставляет fallback.

## DTO порта

Создавать самодостаточный глубоко неизменяемый DTO. Не подменять его application
DTO. Вложенные коллекции преобразовывать в `tuple`, изменяемые структуры — в
заданные неизменяемые DTO или объекты-значения.

## Чистые преобразования

- Не выполнять I/O из mapper-а.
- Не обращаться к clock, ID generator и другим портам.
- Преобразовать всю пачку параметров до первого SQL-вызова.
- Использовать одни parameter mapper-ы в `save` и `batch_save`.
- Не смешивать mapping, дополнительный запрос и семантику отсутствия.

## Типы PostgreSQL

- Сохранять `UUID`, `Decimal`, даты и время в типах контракта.
- Соблюдать timezone-семантику.
- Преобразовывать PostgreSQL enum явно.
- Принимать `NULL` только для optional-поля.
- Считать неизвестный enum, повреждённый JSON и недопустимый `NULL` ошибкой.
- Делать преобразование записи симметричным чтению.
