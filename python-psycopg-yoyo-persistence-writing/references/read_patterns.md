# Чтение, фильтрация и пагинация

## Фильтры

Создавать общий набор условий для `COUNT` и данных:

```python
conditions = [SQL("tenant_id = %s")]
params: list[object] = [tenant_id]

if status is not None:
    conditions.append(SQL("status = %s"))
    params.append(status)

where_sql = SQL(" AND ").join(conditions)
```

Если обязательного фильтра нет, начинать с `SQL("1 = 1")`. Динамические поля
сортировки выбирать из закрытого mapping, а не вставлять из DTO.

Tenant/context/owner scope из контракта включать во все соответствующие
`SELECT`, `UPDATE` и `DELETE`. Не выполнять глобальный поиск перед отдельной
проверкой scope.

## Пагинация

Возвращать неизменяемый DTO порта:

```python
@dataclass(frozen=True, slots=True)
class ItemsPage:
    items: tuple[ItemDTO, ...]
    total: int
```

- Выполнять прямой `COUNT`.
- При `total == 0` не выполнять запрос данных.
- Считать `total` без `limit` и `offset`.
- Использовать устойчивый `ORDER BY` с уникальным tie-breaker.
- Не придумывать ограничения пагинации внутри адаптера.
- Для строгой согласованности выполнять оба запроса в заданном snapshot.
- Не повторять чтение и не подменять `total` при конкурентном изменении.

## Кардинальность

- Различать отсутствие, одну запись и нарушение уникальности.
- Для проверки уникальности при необходимости выбирать максимум две строки.
- Несколько строк вместо уникальной преобразовывать в `AppPortError`.
- Отсутствие возвращать ровно по контракту порта.
- Использовать `EXISTS`, когда данные записи не нужны.
- Проверять `rowcount` изменения, если порт различает отсутствие и успех.

## Пакетное чтение

- Выполнять set-based запрос вместо цикла одиночных вызовов.
- Для пустого набора не выполнять SQL.
- Использовать параметризованный `ANY`, безопасный `IN` или иной механизм
  psycopg.
- Сохранять порядок и обозначать отсутствующие элементы только по контракту.
- Загружать связанные данные пачкой, не создавать N+1.
- Не смешивать scope в пачке, если это не предусмотрено.
- Chunking применять при реальном ограничении или измеренной необходимости.

## Два режима адаптера чтения

- Connection-bound read-репозиторий получает соединение UoW и не арендует новое.
- Standalone read-адаптер получает connection manager и арендует соединение на
  один вызов.
- Не объединять режимы через `connection | manager`.
- Для общего SQL переиспользовать чистый mapper/query component композицией.
