# Чек-листы

## Команда

1. Реализуй одну заданную операцию в принятой структуре бизнес-возможностей.
2. Создай глубоко неизменяемый Command только с минимальным входом.
3. Для partial update различай `UNSET`, `None` и значение.
4. Преобразуй вход в VO до транзакции, если преобразованию не нужен I/O.
5. Для нового агрегата получи ID через типизированный порт, оберни в VO и не
   требуй его в Command без внешней семантики.
6. Выполни только заданную авторизацию и порядок доменных операций.
7. Преобразуй ожидаемые domain-ошибки в публичные application-исходы.
8. Получи новый UoW из обязательной фабрики только для заданной атомарной группы.
9. Сформируй самодостаточные version/outbox DTO в заданных точках сохранения.
10. Верни точный публичный результат без domain-типов.
11. Обнови витрину бизнес-возможности.

## Запрос

1. Реализуй заданную read-only операцию без побочных эффектов.
2. Создай глубоко неизменяемый Query только с минимальным входом.
3. Инжектируй специализированный read-порт напрямую, если транзакция не нужна.
4. Выполни только заданную авторизацию, фильтрацию, сортировку и пагинацию.
5. Верни заданный DTO. Для `limit/offset` с total используй
   `tuple[tuple[DTO, ...], int]`; пустой результат — `((), 0)`.
6. Не добавляй total, если он не требуется.
7. Обнови витрину бизнес-возможности.

## Порты и UoW

1. Создай только требуемые исходящие порты с минимальными контрактами.
2. Используй `ABC`, `@abstractmethod` и тело `...`.
3. Для набора создай используемый batch-метод вместо N+1; коллекции — `tuple`.
4. Вынеси ID, часы, случайность и кеш в отдельные порты; не ограничивай источник
   ID типом UUID.
5. Не размещай `next_id()` в repository-порте.
6. Включай порт в UoW только при участии в одной транзакционной границе.
7. DB-backed источник ID используй через тот же UoW, если резервирование должно
   быть транзакционно связано.
8. Создай `UnitOfWorkFactory`, возвращающую новый UoW для каждого вызова.
9. `__aenter__` возвращает локальный UoW; успех — commit, ошибка/отмена — rollback.
10. Не храни UoW в use case, не вызывай commit/rollback вручную и не используй репозитории после выхода.

## DTO

1. Реализуй точный Command, Query, публичный DTO или внутренний port DTO.
2. Используй `@dataclass(slots=True, frozen=True)`.
3. Используй `tuple` и вложенные frozen DTO вместо `list` и `dict`.
4. Не помещай domain-типы в публичный контракт.
5. Port DTO может содержать domain VO и должен быть самодостаточным для порта.
6. Version DTO фиксирует неизменяемый снимок, тип изменения и заданные метаданные.
7. Outbox DTO содержит минимально достаточные данные для сохранения намерения.
8. Не добавляй I/O, бизнес-поведение и transport-сериализацию.

## Ошибки

1. Перехватывай `DomainError` вокруг минимального доменного вызова.
2. Повторяющуюся карту вынеси в `NoReturn`-транслятор возможности.
3. Неизвестный `DomainError` преобразуй в `AppInternalError`.
4. Адаптер преобразует ошибку зависимости в `AppPortError`.
5. Use case преобразует `AppPortError` в публичный исход со своим `ACTION`.
6. Не перехватывай `BaseException`, `CancelledError` и публичный `AppError`.
7. Логируй итог один раз на внешней границе.

## Тестирование

1. Проверь каждый заданный успешный и ошибочный исход.
2. Проверь точный состав и глубокую неизменяемость DTO.
3. Проверь `UNSET`, `None`, пустые значения и обычное значение.
4. Проверь domain- и port-трансляторы, включая защитный fallback.
5. Проверь новый UoW на каждый вызов, порядок, точки version/outbox и границу UoW.
6. Проверь отсутствие UoW и N+1 там, где они не требуются.
7. Для пагинации проверь непустой результат и `((), 0)`.
8. Используй детерминированные реализации портов ID, времени и случайности.
